    Customizing the Platform 🛠️¶

    While the starter provides powerful defaults (like Trace ID injection, Degraded Mode, and Redaction), you will inevitably need to add your own organization's custom logic to the API responses.

    The ProblemDetailEnricher SPI¶

    The platform exposes an extremely simple Service Provider Interface (SPI): the ProblemDetailEnricher interface.

    Because the starter relies on Spring's auto-wiring of lists (List<ProblemDetailEnricher>), all you need to do is register a new Spring Bean that implements this interface. The platform will automatically discover it and run it for every API error!

    Example: Injecting a Cloud Region ID¶

    Imagine your organization requires every API error to expose which AWS region or Kubernetes cluster served the request.

    import io.github.saul789.api.standard.exception.ProblemDetailEnricher;
import org.springframework.stereotype.Component;
import org.springframework.http.ProblemDetail;
import jakarta.servlet.http.HttpServletRequest;
import java.util.Locale;

@Component
public class CloudRegionEnricher implements ProblemDetailEnricher {

    @Override
    public void enrich(ProblemDetail problem, HttpServletRequest request, Locale locale, Exception ex) {
        // Read from an environment variable or system property
        String region = System.getenv().getOrDefault("AWS_REGION", "us-east-1");

        // Inject the property into the ProblemDetail JSON
        problem.setProperty("cloudRegion", region);
    }

    @Override
    public int order() {
        // Defines the execution order relative to other enrichers.
        // Lower numbers run first.
        return 50; 
    }
}

    Order of Execution¶

    The starter uses the order() method to determine execution sequence. For reference, here are the default enrichers and their orders: - StandardMetadataEnricher (order = 0) - TraceIdEnricher (order = 10) - AnnotationEnricher (order = 20) - DegradedModeEnricher (order = 100) - RedactionEnricher (order = Integer.MAX_VALUE) - Always runs last to mask data added by previous enrichers.

    Bypassing the Platform¶

    If you have a specific controller where you do not want the Global Exception Handler to interfere (for example, a legacy webhook that expects a raw XML string error), you can simply handle the exception manually within the controller using a local @ExceptionHandler or standard try/catch.

    Spring MVC prioritizes local @ExceptionHandler methods inside a @RestController over the @RestControllerAdvice provided by this starter.
