    Error Intelligence Platform 🧠¶

    The V2 release transforms this starter into a full Error Intelligence Platform. It protects your system under load and sanitizes data before it reaches the client.

    🔒 Redaction Engine (Data Masking)¶

    API error responses are a common source of accidental data leaks (PII/Credentials). The Redaction Engine intercepts every ProblemDetail and masks sensitive fields inside validation errors or exposed properties.

    Note: This protects any downstream logs that serialize the error response, but it is not an SLF4J appender (it won't mask manual log.info("password:...") statements).

    api:
  standard:
    redaction:
      enabled: true
      fields: "password, token, secret, credit_card, apiKey, cvv"
      mask: "***"

    JSON Output Example (Validation Error): 

    {
  "type": "https://api.domain.com/errors/validation",
  "title": "Validation Failed",
  "status": 400,
  "detail": "Invalid request body",
  "errors": [
    {
      "field": "password",
      "rejectedValue": "***",  // <--- Masked by Redaction Engine
      "message": "Password must contain at least 8 characters"
    }
  ],
  "traceId": "a1b2c3d4"
}

    🎯 Opt-in Field Exposure¶

    By default, the platform takes a "Secure by Default" approach: custom exception fields are NOT serialized into the JSON response to prevent accidental internal state leaks.

    To expose a safe diagnostic field, annotate it with @ExposeToProblemDetail:

    public class InsufficientFundsException extends BusinessException {

    // This will be added to the JSON as "balance": 10.50
    @ExposeToProblemDetail("balance") 
    private final BigDecimal currentBalance;

    // This will remain hidden
    private final String internalDatabaseId; 

    public InsufficientFundsException(BigDecimal balance, String dbId) {
        super("INSUFFICIENT_FUNDS", "Not enough money", HttpStatus.CONFLICT);
        this.currentBalance = balance;
        this.internalDatabaseId = dbId;
    }
}

    JSON Output Example: 

    {
  "type": "https://api.domain.com/errors/insufficient-funds",
  "title": "Insufficient Funds",
  "status": 409,
  "detail": "Not enough money",
  "balance": 10.50,         // <--- Exposed via @ExposeToProblemDetail
  "traceId": "f9e8d7c6"
  // Note: internalDatabaseId is safely omitted
}

    📉 Degraded Mode (Load Protection)¶

    When the CPU load crosses a dangerous threshold (e.g., 80%), the API enters Degraded Mode. This signals to clients or API Gateways that the service is struggling, allowing load balancers to route traffic elsewhere.

    api:
  standard:
    degraded-mode:
      enabled: true
      cpu-threshold: 80.0

    What the client sees (JSON & Headers): 

    HTTP/1.1 503 Service Unavailable
Content-Type: application/problem+json
X-API-Degraded: true       // <--- Added to HTTP Headers

{
  "type": "https://api.domain.com/errors/service-unavailable",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "The service is temporarily unable to process the request.",
  "degraded": true,        // <--- Added to the ProblemDetail
  "traceId": "x9y8z7"
}
